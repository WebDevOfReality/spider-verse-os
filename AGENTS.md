# AGENTS.md — Spider-Verse OS

> **This file is a binding directive, not documentation.** It governs how any AI
> agent, coding assistant, or automation tool may operate in this repository.
> Violations of the AI Ethics Directive below are build-breaking.

## What this project is

**Spider-Verse OS** ("Weaver") — a from-scratch Linux distribution, built for
the Spider-Verse: kernel + initramfs core with the mesh network (Nebula, the
"Web of Reality") built into the OS image. Everything is compiled from source
with our own cross-toolchain. See `README.md` for the plan and `docs/` for the
stage roadmap.

## AI Ethics Directive (NON-NEGOTIABLE)

This project is part of the WebDev of Reality brand and inherits its
**ethical AI** rules. Violations fail review and may fail the build.

### 1. Transparency: label and sign all AI content

- Any source, script, doc, or config **substantially generated by AI** must be
  disclosed in the commit message:
  - `ai-assisted: <model name and version, e.g. GLM (glm-5.3-flash) by Z.ai>`
- AI-written docs that teach (roadmaps, guides) carry a provenance note in the
  file header.
- Unsigned AI work must never ship.

### 2. No AI-generated art — ever

- **Never** generate, upsert, or commit AI-generated images, logos, icons,
  boot splashes, mascots, or any other visual asset — including
  "placeholders."
- All visual identity is made by Anthony by hand (ASCII is fine, crude is
  fine, human-made is the point).
- If a task requires new artwork: leave a `TODO(art:)` note and stop.

### 3. Human authorship is the default

- Design decisions, architecture, and the roadmap are Anthony's. AI may draft
  code/docs at his explicit request, grounded in his decisions, and labeled.
- When Anthony is learning (this is a learning project by design), AI
  **explains and reviews** — it does not silently take over the hands-on work.

### 4. Engineering conventions

- **Toolchain/kernel/init code** (`toolchain/`, `kernel/`, `init/`): changes
  here should be understood by a human. AI may propose patches, but anything
  merged into PID 1 or the kernel config must be explained line-by-line on
  request.
- **Timeboxes:** stages are timeboxed (see README). If AI is asked to unblock
  a stuck stage, it must summarize *what was learned* so the vlog/blog keeps
  its educational value.
- **No secrets** in the repo. Nebula CA keys and certs are generated locally,
  never committed.
- **Commits:** small, honest messages; append the `ai-assisted:` line when a
  change was substantially generated by AI.

## Definition of done for any stage

- [ ] Exit criterion met (see README stage table)
- [ ] `make` (or stage equivalent) reproducible from a clean checkout
- [ ] CI green (build + QEMU smoke test)
- [ ] Docs updated (stage notes = vlog/blog material)
- [ ] No AI-generated art, unsigned AI code, or secrets
